# Yunvia — Roadmap

Roadmap status: **proposed**. Order is intentional; dates and estimates are not committed.

## Phase 0 — Foundation (now)

**Deliverables**
- [x] Agree on mission, name, and high-level principles.
- [x] Create a GitHub repository and initial project documentation.
- [ ] Confirm brand availability (trademarks, domains, app stores) before public marketing.
- [ ] Select a software license, contribution guidelines, conduct policy, and private security-reporting route.
- [ ] Interview potential participants and identify one Puerto Rico pilot community.
- [ ] Choose one low-risk flagship project (for example, a small tool-sharing initiative).
- [ ] Make architecture decisions, local development setup, and deployment plan.
- [ ] Define minimal platform-wide conduct and moderation rules.

**Exit condition:** a pilot partner, a clearly defined first use case, and an implementable technical plan.

## Phase 1 — Working MVP

Build a **project-first, mobile-friendly, bilingual** application.

### Required user journeys

1. A member creates an account and sets an optional approximate locality.
2. A member creates or joins a community through a clear membership flow.
3. An authorized member proposes a project with an outcome, description, and milestones.
4. Members view project needs and offer skills, time, materials, or equipment.
5. Project coordinators can accept/organize offers and update milestone progress.
6. Community members can see project status and coordinate through basic discussion/comments.
7. Members can report harmful content or users; moderators have a defined review process.
8. Members can manage visibility of their information and leave a community.

### MVP capabilities

- Account authentication and editable profile.
- Communities, memberships, simple roles.
- Projects, milestones, resource needs, voluntary pledges.
- Basic updates/comments and notifications (in-app at minimum).
- Spanish/English language support and baseline accessibility.
- Permission checks and audit records for consequential actions.
- Reporting, blocking, and essential moderation flow.
- Data export path for an individual's own information (implementation detail to decide).

### MVP exclusions

- Yunvia-held payments or wallets, cryptocurrency, time-credit accounting.
- Algorithmic reputation scores and auto-generated skill rankings.
- AI-generated recommendations.
- Federation and self-hosting workflows.
- Advanced voting, complex governance plugins, or multi-community networks.
- Guaranteeing emergency connectivity or providing emergency dispatch.

**Exit condition:** a usable end-to-end project journey tested with pilot participants, including privacy/accessibility/safety checks.

## Phase 2 — Local pilot

Start with **one community**, not an island-wide launch.

Suggested process:
- Recruit approximately 30–50 interested participants with a local partner (targets, not guarantees).
- Co-design a concrete shared project and help members onboard.
- Observe whether contributions turn into actual completed work.
- Interview both active and inactive participants.
- Review safety, moderation burden, and accessibility issues.
- Fix retention and workflow failures before broad recruitment.

**Pilot evidence to collect**
- Projects completed; contribution offers made versus fulfilled.
- Participation breadth and repeat collaboration.
- Member-reported usefulness and trust.
- Time/effort required by coordinators.
- Serious unresolved safety problems.
- Failure reasons, not just success stories.

**Go/no-go:** expand only when real participants repeatedly coordinate meaningful work with manageable overhead and acceptable safety outcomes.

## Phase 3 — More capable communities

After pilot validation, consider:
- Reusable **community project blueprints**.
- Shared inventory and tool-reservation workflows.
- Coordination for collective purchasing (payments remain external initially).
- Deeper decision-making and governance options.
- Better moderation/admin transparency and local reporting.
- Data portability and community exports.

## Phase 4 — Networks

Only when local community use is proven:
- Voluntary intercommunity collaboration.
- Localized deployment in additional regions and languages.
- Independent hosting/federation exploration.
- Potential integrations with existing cooperative organizations.

## How we prioritize

A feature is high priority when it improves completion of a real community project, reduces coordinator workload, protects users, or makes the experience meaningfully more accessible. An impressive demo that does not improve these outcomes is lower priority.

## Current open decisions

- Pilot partner and initial project.
- Final license and organizational steward.
- Authentication and hosting provider.
- Community discovery/privacy model.
- Moderation workflows, appeals, and retention policy.
- Exact MVP acceptance tests and analytics consent.
